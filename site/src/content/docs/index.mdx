## Same values. Different entities.

**Values describe content. References preserve identity.** Two services can have
identical settings. A reference says **which one** a link reaches.

<div class="identity-example">
  <div>
    <h3>Why does immutable data need references?</h3>
    <p><strong>Not for mutation. For identity and relationships.</strong></p>
    <p>Give two services the same <code>port: 8080</code>, then connect the first to the second. Their content is equal; their places in the model are distinct.</p>
    <p>References compare canonical target paths; ordinary values compare content. Moving an entity to a different key or index changes its identity in the model.</p>

## More semantics, not more programming.

Immutable values. Pure evaluation. Deterministic results. A terminating core.
Decl focuses on describing the meaning of data; the host application handles I/O
and workflows. Read [why Decl is shaped this way](/guide/00_why_decl/).

Applications can use that meaning too.
[Decl for AI agents and conceptual models](/guide/07_using_the_model/) shows how
existing models and diagnostics can guide another tool's work.

## Use Decl in your project

Install the implementation that fits your environment. All three share the same
specified behavior and ship the CLI, formatter, and language server.

<Tabs syncKey="channel">
  <TabItem label="npm">
    ```bash
    npm install -g decl-lang
    ```
    TypeScript reference implementation. Node.js ≥ 22.
  </TabItem>
  <TabItem label="pip">
    ```bash
    pip install decl-lang
    ```
    Native Python implementation and Python API.
  </TabItem>
  <TabItem label="cargo">
    ```bash
    cargo install decl-lang
    ```
    Native Rust implementation.
  </TabItem>
  <TabItem label="brew">
    ```bash

    ```
    The npm package through the Homebrew tap.
  </TabItem>
